`stroke=currentColor`, `fill=none`, round caps and joins, at most 12 strokes, 2px safe margin, no
text, no fills, no gradients, no transforms). Round 1 was the Claude draughtsman run through the
icon-smith loop (`python -m figtree icon ... --backend claude`); round 2 was a hand edit of the
inner markup after a cold read of the rendered sheet at 16/24/48/96 px on light and dark, then a
re-score with the icon rubric. Scores are the icon rubric overall (1-10); acceptance is >= 9.5.

## What the loop caught that the first draft missed

The measurable critic scored every round-1 icon 10.0, so the defects that mattered were only
visible in the image space: sub-pixel text stubs (grounder), a pencil that was not a pencil
(draw-leaf), a wrench that was a notched circle (repair), and strokes colliding at 16px (merge,
edit-script, critic's slit eye). Rendering the sheet at 16px beside 96px was the step that
exposed them, which is exactly the dual-space review the critic prescribes but cannot yet do
without a VLM. One rubric defect surfaced in the other direction: the coverage check under-reads
multi-segment relative path commands, so the critic icon had to be rewritten with polylines to
score what it already drew.

## Timeline of the page (one clock for figure and captions)

Motion grammar as in `docs/META-PROMPT-SVG-ARTIFACTS.md`: reveal = construction order (containers
appear with their first block), draw = connectors, after both endpoints exist (a marker-less
`ft-shaft-N` draws itself, then the real arrow with its head appears), pulse = a token travelling a
data flow; the dashed control edge `re-validate invariants → render` gets a slower (half speed)
and dimmer (#9A9A9A) token. Nothing else moves.

| Beat | Starts | What happens in the figure |
|---|---|---|
| 1 Grounding | 0.0 s | container n2 (0.3), Grounder (0.6) |
| 2 Recursive construction | 3.0 s | Generator (3.1), container n3 (3.7), Decompose children (3.9), Generator → Decompose drawn (4.4), recursive tree (5.2), Grounder → recursive tree drawn (5.7) |
| 3 Merge | 7.6 s | container n4 (7.8), Merge (8.0), Decompose → Merge drawn over 1.0 s (8.5) |
| 4 Render–critic loop | 10.6 s | Critic (10.8), Merge → Critic (11.2), tree → Critic (11.5), container n5 (12.2), Worker (12.4), Critic → Worker (12.8), re-validate (13.3), Worker → re-validate (13.7), render (14.2), dashed control edge (14.6), render → Critic feedback over 1.0 s (15.4) |
| 5 Editable output | 17.0 s | tokens start; one 9.92 s cycle: Grounder/Generator tokens → Decompose/tree tokens (the long bus to Merge and the drop to Critic) → Merge → Critic → Worker → re-validate → (control, slow, grey) render → feedback back to Critic → rest → repeat |

Token speed is 240 px/s of path length (minimum 0.35 s per hop), so a token on the 680 px bus takes
2.8 s and a 24 px hop takes 0.35 s; the per-token keyframes hold at 0 % and 100 % so every token
shares the same cycle period and the chain stays in order.

The caption strip is highlighted with the same CSS delays (`--on`/`--off` per caption). Replay,
pause, a scrubber and clickable captions seek every animation through the Web Animations API
(`Animation.currentTime`); the page keeps its own clock from `performance.now()`.
`?theme=dark|light` forces a theme, `?motion=reduce` previews the reduced-motion fallback (the
media query is also honoured): final state, shafts and tokens hidden, all captions lit, controls
hidden.

6 · The meta-prompt behind all of it

The category is editable-SVG artifact synthesis under a rubric. What varies per instance is the source, the medium and the motion grammar; what never varies is the loop. The full typed version lives in docs/META-PROMPT-SVG-ARTIFACTS.md; this is its skeleton.

Typed slots

  • Source · Medium · Rubric(Medium)
  • Vocabulary of element kinds · IconFamily · MotionGrammar
  • ContentPlan with evidence spans
  • LayoutTree (2–4 children, depth ≤ 8, ≤ 32 nodes)
  • Program · Render · CriticReport · EditScript
  • Trajectory · Convergence · Requests

Procedure

  1. Ground: only evidenced elements, nothing invented
  2. Choose vocabulary and motion by meaning
  3. Construct recursively; parents own cross-boundary arrows; 20 px shafts
  4. Critique in two spaces, every issue anchored
  5. Edit locally; hand content decisions back
  6. Score, loop until stable, keep the trajectory
  7. Promote: icons to the family, rules to memory

Binding rules

  • The content plan is immutable downstream
  • Ids are stable; edits address existing ids
  • Data flow → pulse; control → slower pulse; construction → reveal and draw
  • No evidence → not assessed, never a 10
  • Fixed canvases centre; free canvases shrink

Refinement log

  • Pass 1 added icons and motion as slots
  • Pass 2 bound motion to flow types; fixed score inflation
  • Pass 3 separated fixed from free canvases
  • Pass 4 returned an empty edit script

## Observations beyond the table

- **Score saturation.** Thirteen of fourteen gaming figures score a flat 10.0: with no source or
  plan, `semantic_coverage` and `hallucination_control` are unassessed, so a figure that is
  geometrically tidy and semantically wrong is indistinguishable from a good one. The veto cap on
  `medium_fit` only applies when a *measurable* check fires, so none of the judge-only vetoes
  (clip art, textual overload, embedded title, decoration) ever reach it.
- **Endpoint exclusion is the dominant through-block hole.** Three probes (`edge_hugging_arrow`,
  `arrow_exits_through_source`, `arrow_through_text`) defeat occlusion detection by touching a
  boundary, by sharing an endpoint, or by not being a block at all. A halo plus clipping at the
  port fixes the first two in one place.
- **The 0.5em estimator is wrong in both directions.** Measured widths: caps run 0.65-0.72em
  (`WORKFLOW MANAGER` 156px vs 112 estimated), narrow lower-case runs 0.36-0.45em
  (`Initialisation` 71px vs 98). A 95-entry width table for the house font removes both the
  gaming and the false positive; `overflow_inherited_font` additionally needs the resolved size.
- **Snake layouts trip `flow.reading_order`.** The first draft of the clean probe was a 2x3 snake
  (row 2 reads right-to-left back to the start) and fired reading_order at forward_ratio 0.5; a
  ring or snake laid out as a closed cycle always has about half its arrows against reading
  order, so the 0.6 threshold should be evaluated per row/column or on the dominant axis.
- **Polylines are invisible.** `is_flow` accepts polylines but `load_program` never fills their
  points, so every flow check (through-block, crossings, diagonal, short shaft, detour) is blind
  to them and reading_order counts them as backward.
- **File naming.** The task text said `<id>.svg`; the sibling adversaries use `<slug>.svg`, so
  this set follows the directory convention (the `id` field in the JSON is authoritative).

## Patterns across the probes

1. **The data-figure rubric measures typography and colour, not the data encoding.** All ten
   data-figure gaming probes score 10.00 and six of them (dual axis, truncated axis, bars
   not to scale, legend mismatch, missing units, 3D) misstate the data. The rubric
   description promises "labelled axes with units ... no 3D or gradients"; only the gradient
   half is measured. The cheapest high-value additions are `proposed.axis_units`,
   `proposed.bar_axis_zero` and `proposed.legend_swatch_colour`, all computable from ids and
   attributes already present.
2. **`AXIS_WORDS` is the single weakest regex.** The alternatives `%`, `$`, `€`, `£` and
   `\(.*\)` are wrapped in `\b` and never match in practice; the words that do match
   (`time`, `loss`, `score`, `count`, `per`) let unit-less labels, pie subtitles and
   footnotes pass. One false positive (`units_in_parens_unrotated`) and two gaming probes
   (`axis_labels_no_units`, `pie_paths`) hinge on it.
3. **Text geometry is the source of every false positive.** `rotate(-90)` without a centre,
   rotation by any angle other than +-90, and the 0.5 em glyph estimate each produce a
   critical issue on a correct chart (`compactness.overflow`, `text.overlap`), each of which
   caps a dimension at 5 and would push the refiner to "fix" a correct label.
4. **Host detection ignores paths.** Any chart library that emits bars, areas or slices as
   `<path>` gets no contrast check on labels inside them (`label_on_path_bar_contrast`), and
   `path_to_points` drops arc and curve commands, so a pie's bbox is wrong too.
5. **Dashboard checks stop at the tile border.** Hierarchy inside a tile, status colour
   semantics, sparkline references and grid uniformity are all unmeasured; the four
   dashboard gaming probes score 10.00.

## Measurable motion checks (what to parse)

All of these read the `<style>` block of the animated SVG (or the sibling stylesheet) with a
small CSS tokenizer: `@keyframes NAME{...}` → per-keyframe property map; `#ID{...}` → declared
properties; `animation:` shorthand → (name, duration, timing, delay, iteration, direction) per
comma-separated entry; `@media (...)` → nested rules. They then join on element ids against
`load_program(svg)`.

| check | parse | rule |
|---|---|---|
| `motion.pulse_direction` | for each rule with `offset-path: path('D')`: the element id, `D`, its `ft-travel`-like keyframes (`offset-distance` at from/to), `animation-direction` | find the flow whose `d` (or `points_to_path(points)`) equals `D`; the offset-distance sequence must be non-decreasing over time (0% → 100%); `direction: reverse` or `alternate` on a token is a violation; a `D` equal to a flow's reversed point list is a violation |
| `motion.reveal_order` | every rule whose animation name's keyframes go opacity 0 → 1 (reveal), its delay, and the block/group it targets | order blocks by `(bbox.y // 64, bbox.x)` as `animate._order` does; Spearman rank correlation between that order and delays must be >= 0; additionally for every flow, delay(target group) >= delay(source group) |
| `motion.draw_after_endpoints` | rules on `ft-shaft-*` (stroke-dashoffset keyframes) with delay | delay(shaft) >= delay(source group) + reveal duration and >= delay(target group) + reveal duration |
| `motion.control_tempo` | per token: path length of `D` (Manhattan over `path_to_points`), duration, the token's fill; the flow's `data-flow` | speed = length/duration; max control speed <= min data speed; relative luminance of control fill > data fill; control tokens may not be larger (`r`) than data tokens |
| `motion.reduced_motion` | presence of `@media (prefers-reduced-motion: reduce)` and the rules inside it | every id animated outside the block must inside it get `animation: none` (or the universal rule) with its final values (`opacity: 1`, `stroke-dashoffset: 0`); every `[id^=ft-pulse]`/`[id^=ft-shaft]` must be `display: none` there; a missing block is critical |
| `motion.decorative` | every `offset-path` `D`; every `animation` entry's target element and iteration count; the animated properties of each keyframes block | each `D` must equal a flow's path (data-flow or marker-end) in forward order; `infinite`/`alternate` is allowed only on `data-role=pulse` tokens; blocks and labels may animate `opacity` once (reveal) and nothing else; shafts may animate `stroke-dashoffset` only; any other property (`transform`, `fill`, `stroke`, `r`, `filter`) is decoration |
| `motion.token_static_position` | each `data-role=pulse` element's `cx/cy` | must be on the first point of its `offset-path`, with `transform-box: fill-box; transform-origin: center` in its rule; this also keeps the static critic from reporting overflow |
| `motion.total_duration` | max(delay + duration) over non-infinite entries | <= the explainer's budget (e.g. 20 s) so the construction finishes before the captions do |

A rendered check complements these: capture frames at `t = delay(token) + 0.25 * duration` and
`+ 0.75 * duration`, locate the token (its fill colour) and verify the second position is farther
along the flow than the first; capture once with `--force-prefers-reduced-motion` at `t = 0.5 s`
and require the frame to equal the final frame.

Contract and process

The pipeline and the design meet at a typed contract, FigureProgram (design/contract/): design-free ids, boxes, kinds, tones, icons and flow types that any renderer can draw and the critic can still read. python -m figtree contract export|validate|render round-trips a figure; the design system renders the same program through its house adapter, the paper preset or a swapped adapter. How the effort itself is run (meta-prompt first, self-apply, tiny-context workers, adversarial fold, package every round) is the figtree-process skill, and docs/HANDOFF.md is the four-level handoff.

What the loop caught, and what the eye caught

  • CSS transform on an SVG group replaces its own translate: an animated block jumped to its container's corner. Reveal now animates opacity only.
  • A marker-ended path with a hidden shaft still paints its arrowhead: the "standalone triangle" the paper warns about appeared during draw-on. A marker-less shaft copy draws first; the real connector appears when it is complete.
  • Raising fonts to a medium's minimum is mechanical, but it creates overflow and collisions on long labels in the same round; the edit script has to shorten labels at once.
  • Text over a gradient fill passed a contrast check against the canvas; the critic now refuses to certify contrast on gradient hosts.
  • Neon was checked on fills only; a neon stroke survived. Strokes are checked now.
  • "Has a title that states the finding" accepted any three-word label (a legend entry); it now checks the most prominent text.
  • A model grounder also returns a global style; adopting it replaced the paper palette with saturated fills. The content plan is kept, the style is not, unless asked.
  • Shrinking a slide or an icon canvas to its content breaks the medium; fixed canvases centre their content instead.
